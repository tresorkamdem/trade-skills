## 2. Les bases de Pine Script (v6)

Pine exécute ton script **une fois par bougie**, de la plus ancienne à la plus récente. Chaque variable est une **série** : `close` est la clôture courante, `close[1]` celle de la bougie précédente, `close[5]` celle d'il y a cinq bougies.

```pine
//@version=6
indicator("Ma moyenne", overlay = true)
len = input.int(50, "Longueur")
mm = ta.sma(close, len)
plot(mm, color = color.orange)
```

| Notion | Exemple |
| --- | --- |
| Entrées réglables | `input.int`, `input.float`, `input.bool` |
| Fonctions techniques | `ta.sma`, `ta.ema`, `ta.rsi`, `ta.atr`, `ta.highest`, `ta.crossover` |
| Variable persistante | `var float stop = na` (gardée d'une bougie à l'autre) |
| Affichage | `plot`, `plotshape`, `hline`, `bgcolor` |
| Alertes | `alertcondition` (choisie dans la fenêtre d'alerte), `alert()` (message dynamique) |

Les fonctions de `tradeskills/indicators.py` donnent les mêmes valeurs que `ta.*` : tu peux vérifier un calcul Pine en Python.

## 3. Tes trois scripts, expliqués

### `systeme_tendance_indicateur.pine`

```pine
trend   = ta.sma(close, lenTrend)            // MM200 : le filtre
upper   = ta.highest(high, lenEntry)[1]      // plus haut des 20 bougies PRÉCÉDENTES
lower   = ta.lowest(low, lenExit)[1]         // plus bas des 10 bougies précédentes
atrVal  = ta.atr(atrLen)
signalAchat  = close > trend and ta.crossover(close, upper)
signalSortie = ta.crossunder(close, lower)
stop = close - atrMult * atrVal
```

Le `[1]` est indispensable : sans lui, le plus haut des 20 dernières bougies **inclut la bougie courante**, et la clôture ne peut presque jamais le dépasser (elle est sous le plus haut de sa propre bougie). L'indicateur affiche des triangles verts (achat) et des croix rouges (sortie), et déclenche des alertes au **format JSON** que le serveur `node/webhook.mjs` comprend.

### `systeme_tendance_strategie.pine`

La même logique, mais en `strategy()` : TradingView simule les ordres, avec 10 000 € de capital, **0,05 % de commission** et **2 ticks de glissement**, et une taille à risque fixe :

```pine
stopPrice := close - atrMult * atrVal
qty = math.floor(strategy.equity * riskPct / (close - stopPrice))
```

C'est exactement `risk.position_size`. Les résultats sont dans l'onglet **Strategy Tester**.

### `rsi_divergence.pine`

Un RSI avec ses zones 30/70 et un repérage des **divergences haussières** : le prix fait un plus bas plus bas, mais le RSI fait un plus bas plus haut. Le script mémorise le dernier pivot bas avec des variables `var`, et décale l'affichage de `look` bougies (`offset = -look`), car un pivot n'est confirmé qu'après coup.

## 4. Indicateur ou stratégie

- `indicator()` affiche des informations et des signaux.
- `strategy()` simule des ordres et produit un rapport : rendement, perte maximale, nombre de trades, **profit factor** (gains bruts / pertes brutes).

Paramètres à toujours renseigner dans une stratégie : `initial_capital`, `commission_value`, `slippage`. Sans coûts, un backtest ment.

## 5. Les pièges du backtest sur TradingView

| Piège | Explication | Parade |
| --- | --- | --- |
| Repainting | Un signal apparaît puis disparaît, car calculé sur une bougie non clôturée ou avec des données futures (`request.security` mal utilisé) | Signaux à la clôture (`barstate.isconfirmed`, `alert.freq_once_per_bar_close`), `lookahead = barmerge.lookahead_off` |
| Historique limité | Le nombre de bougies dépend de l'abonnement | Backtester en Python sur une longue histoire |
| Sur-optimisation | Régler les paramètres jusqu'à ce que la courbe soit belle | Module 07 : walk-forward et hors échantillon |
| Exécution irréaliste | Achat au plus bas de la bougie | Ordres au marché à l'ouverture suivante, glissement |

Le message d'alerte est du JSON :

```json
{"type":"achat","symbole":"{{exchange}}:{{ticker}}","prix":{{close}},"stop":123.4,"strategie":"mon_setup"}
```

`type` vaut `achat` ou `sortie` ; garde la bourse devant le code (`XETR:SXR8`), elle sert à retrouver le code Yahoo (`SXR8.DE`).

::: attention
**Où en est ce pont chez toi** : la poche `tradingview` existe et tourne chaque soir, mais elle reste sans trade, pour deux raisons. Les webhooks demandent un plan payant, et le serveur Node doit être joignable depuis Internet alors que le passage du soir tourne sur GitHub. La solution prévue passe par SESHAT (Supabase) ; on la construira quand tu prendras un plan payant. En attendant, tu peux t'entraîner avec les alertes simples (notification dans l'application TradingView de ton iPhone).
:::

## 7. Organisation du travail

- Un script = un fichier dans `pine/`, versionné dans Git.
- Toute stratégie Pine prometteuse est **revérifiée en Python** sur une histoire plus longue et hors échantillon avant d'être tradée.
- TradingView sert à **voir et alerter** ; Python sert à **valider** ; les agents servent à **exécuter sans émotion**.

::: retenir
1. Pine tourne bougie par bougie ; `[1]` regarde en arrière.
2. Une stratégie sans coûts ni glissement ment.
3. Méfie-toi du repainting : signaux à la clôture uniquement.
4. TradingView sert à voir et à alerter ; Python sert à valider.
:::

## Solutions pas à pas

::: solution
**Exercice 1 · Premier indicateur**

```pine
//@version=6
indicator("MM50 / MM200 et fond de tendance", overlay = true)
mm50  = ta.sma(close, 50)
mm200 = ta.sma(close, 200)
plot(mm50,  "MM50",  color = color.blue)
plot(mm200, "MM200", color = color.orange, linewidth = 2)
bgcolor(mm50 > mm200 ? color.new(color.green, 88) : na)
```

*Étapes* : Pine Editor → colle → **Cmd + S** → nom « MM tendance » → **Add to chart**. `color.new(color.green, 88)` donne un vert transparent à 88 %, pour ne pas masquer les bougies. Le fond vert recouvre les longues périodes où la tendance de fond est haussière (« golden cross »).
:::

::: solution
**Exercice 2 · Lire le système**

*Ligne par ligne* :

1. `input.int(200, ...)` et suivantes : les réglages, modifiables dans la roue dentée de l'indicateur sans toucher au code.
2. `trend = ta.sma(close, lenTrend)` : la MM200, filtre de tendance.
3. `upper = ta.highest(high, lenEntry)[1]` : le plus haut des 20 bougies **avant** la bougie courante.
4. `lower = ta.lowest(low, lenExit)[1]` : le plus bas des 10 bougies avant.
5. `signalAchat = enTendance and ta.crossover(close, upper)` : la clôture *franchit* le plus haut, dans une tendance haussière. `crossover` ne vaut vrai que le jour du franchissement, pas les jours suivants.
6. `stop = close - atrMult * atrVal` : le stop proposé, envoyé dans l'alerte.
7. `plotshape` : les triangles et les croix.
8. `alertcondition` et `alert()` : les alertes, au format JSON.

*Pourquoi `[1]`* : sans décalage, `ta.highest(high, 20)` inclut le `high` du jour. Or `close ≤ high` toujours. La condition `close > upper` serait donc presque toujours fausse. En Python, `indicators.donchian` fait le même décalage avec `.shift()`.
:::

::: solution
**Exercice 3 · Backtest TradingView** (méthode et lecture)

1. Pine Editor → colle `systeme_tendance_strategie.pine` → **Add to chart**.
2. Onglet **Strategy Tester** → **Overview** et **Performance Summary**. Relève : *Net Profit*, *Max Drawdown*, *Total Closed Trades*, *Profit Factor*.
3. Change de symbole (Cmd + K) : SXR8, EXS1, EURUSD. La stratégie se recalcule.
4. Roue dentée → onglet **Properties** → commission 0, slippage 0. Relève à nouveau.

*Ce que tu dois observer* : sur un indice en tendance (S&P 500), le profit factor est souvent supérieur à 1,3 ; sur l'EUR/USD, qui tend moins, nettement plus faible. Sans coûts, le résultat s'améliore d'autant plus que les trades sont nombreux. Si le nombre de trades est inférieur à 30, **aucune conclusion n'est possible** (module 05, exercice 3).

*Limite du plan gratuit* : l'historique disponible est plus court que sur les plans payants. C'est une raison de plus pour se fier à la Time Machine en Python.
:::

::: solution
**Exercice 4 · Sensibilité** (méthode)

Fais un tableau de 3 × 3 = 9 cases, une par couple (entrée, stop), avec le profit factor dans chaque case.

| | stop 1,5 ATR | stop 2 ATR | stop 3 ATR |
| --- | --- | --- | --- |
| entrée 10 | | | |
| entrée 20 | | | |
| entrée 55 | | | |

*Lecture* : si les 9 cases sont proches (par exemple toutes entre 1,2 et 1,6), le système est **robuste** : il ne dépend pas d'un réglage précis. Si une seule case brille et les autres sont sous 1, c'est de la **sur-optimisation** : le « bon » réglage est un accident de l'échantillon. Rappel du module 03 : sur des prix aléatoires, 24 % des réglages battent l'achat-conservation.
:::

::: solution
**Exercice 5 · Repainting**

*Ce qui se passe* : le nombre de trades s'effondre (presque aucun), car la clôture dépasse rarement le plus haut qui inclut sa propre bougie.

*Variante plus dangereuse* : si on compare `high > ta.highest(high, 20)` (au lieu de `close`), le signal peut apparaître **pendant** la bougie puis disparaître à la clôture. En temps réel, tu aurais vu des alertes qui n'existent plus sur le graphique le lendemain : c'est le **repainting**. Un backtest sur ces signaux est faux, puisqu'il ne montre que les signaux qui ont survécu.

*Parade* : signaux calculés à la clôture confirmée, alertes en `alert.freq_once_per_bar_close`, toujours `[1]` sur les niveaux de cassure.
:::

::: solution
**Exercice 6 · Rebond sur MM50**

```pine
//@version=6
strategy("Rebond MM50", overlay = true, initial_capital = 10000, currency = currency.EUR,
     commission_type = strategy.commission.percent, commission_value = 0.05, slippage = 2)
riskPct = input.float(1.0, "Risque par trade (%)") / 100
atrMult = input.float(1.5, "Stop en ATR")
mm50  = ta.sma(close, 50)
mm200 = ta.sma(close, 200)
atrV  = ta.atr(14)
plusHaut = ta.highest(high, 20)[1]   // calculé à chaque bougie, hors du if (règle de Pine)
// Contexte : tendance haussière ; la bougie a touché la MM50 et clôture au-dessus, en hausse
rebond = close > mm200 and low <= mm50 and close > mm50 and close > open
var float stopP = na
var float cible = na
if strategy.position_size == 0 and rebond
    stopP := math.min(low, close - atrMult * atrV)
    cible := plusHaut
    qty = math.floor(strategy.equity * riskPct / (close - stopP))
    if qty > 0 and cible > close
        strategy.entry("Long", strategy.long, qty = qty)
if strategy.position_size > 0
    strategy.exit("Sortie", "Long", stop = stopP, limit = cible)
plot(mm50, "MM50", color = color.blue)
plot(mm200, "MM200", color = color.orange)
```

*Points de contrôle* : le stop est le plus bas des deux (plus bas du rebond ou 1,5 ATR), l'objectif est le plus haut précédent, et on n'entre que si l'objectif est au-dessus du prix. Enregistre-le dans `pine/rebond_mm50.pine` et compare ses résultats à ceux de la cassure Donchian (exercice 3).
:::
